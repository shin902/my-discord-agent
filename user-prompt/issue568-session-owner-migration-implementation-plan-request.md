# 成果物

- 配置先: `design-docs-for-ai/` 配下のマークダウンファイル 1 つ
- ファイル名: `issue<番号>-<内容の英語要約>-implementation-plan.md`（スコープが PR 単位の場合は `issue<番号>-pr<番号>-<内容の英語要約>-implementation-plan.md`）

この実装計画は、本セッションの文脈を持たない別の AI コーディングエージェントがそのまま実装に使います。人間が読むことは想定していません。追加の調査や質問なしで実装に着手できる、それ単体で完結した内容にしてください。

構成・フォーマットは指定しません。課題ごとに最適な書き方は異なるため、この課題に最適だと考える形で書いてください。

実装計画内にコードブロック（実装例・変更後のコード等）を書く場合は、先に以下の Skill を読み込み、その内容に従って命名とコメントを書いてください。

- `code-naming`: 変数・関数・メソッド・クラス・型・ファイルの命名規則
- `code-comments`: コード・テストコード・コミットログ・コードコメントの書き分け

実装計画に必ず含めるもの:

- 変更対象ファイルの一覧と、それぞれの変更内容
- 利用するライブラリ API の、現在インストールされているバージョンでの正しい書き方（根拠として参照した一次情報の URL を併記する）
- テスト方針（テスト対象・配置場所・観点）
- 品質管理の手順（ルートの CLAUDE.md「品質管理の実行手順」に従う）
- ブラウザ確認は計画に含めない。Discord での実地確認は依頼者が別途その場で行う

`design-docs-for-ai/` に過去の実装計画が残っている場合がありますが、古い前提を含んでいる可能性があるため参照しないでください。事実確認は現行のコードと一次情報で行ってください。

# 進め方の境界

- コードの読解・`gh` での Issue 取得・ドキュメント調査・ブラウザでの現状確認は、確認なしで進めてください
- Issue の記述と実際のコードが矛盾している場合や、要件の解釈次第で設計が大きく変わる場合は、推測で確定せず私に確認してください

# 環境情報

- サーバー（開発サーバー・Storybook）は起動済みとは限りません。git worktree で並列開発している場合もあり、その際は起動済みのサーバーが別の作業ディレクトリのコードを配信していることがあります。動作確認の前に、確認対象が今の作業ディレクトリのコードであることを確かめ、必要なら空いているポートで自分で起動してください
- ドキュメント調査の手段は指定しません。このセッションで利用可能な手段を選んでください。Discord ブラウザ操作は行いません
- Figma デザインの確認だけは、スクリーンショット等で代用せず Figma の MCP サーバーを使ってください
