# セキュリティ上のトレードオフ

意図的に受け入れたセキュリティリスクの記録。

## サンドボックスのプライベートIP egress

**場所:** `src/agent/manager.ts` — `NetworkPolicy.builder().egress(rb => rb.allowPrivate())`

**内容:** サンドボックスコンテナからプライベートIPアドレス（`10.x.x.x`・`192.168.x.x`・`172.16-31.x.x`）への送信を許可している。

**理由:** 同一LAN上の別PCで動作するローカルLLMサーバーへの接続に必要。`allowHost()` はホスト名ベースのルールのため、プライベートIPに解決されるホストへの通信は `allowPrivate()` がないとブロックされる。

**残存リスク:** `url-fetch` ツールでのDNSリバインディング攻撃と組み合わさった場合、悪意あるURLを経由してLAN内部サービスへ到達できる可能性がある。ただし実行環境がサンドボックスコンテナ内であるため影響範囲は限定的。

**対策済み内容:**
- `url-fetch.ts` の `isPrivateAddress()` で解決済みIPをチェック（全アドレス検査）
- `allowLoopback()` は不要なため削除済み（コンテナ自身への接続を排除）

## DNSリバインディング（TOCTOU）

**場所:** `src/tools/url-fetch.ts` — `lookup()` 後に `curl`/`yt-dlp` が内部で再度DNS解決する

**内容:** Node.jsの `lookup()` でIPを検証した後、実際のコマンド実行までの間にDNSレコードが書き換わる可能性がある。

**理由:** `curl`/`yt-dlp` の接続先IPをアプリ層で制御する手段がない。ネットワーク層での制御（ファイアウォール等）が本来の対策だが、ローカルLLMのために `allowPrivate()` が必要なため完全なブロックができない。

**残存リスク:** 上記プライベートIP egress の項を参照。
